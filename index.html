APPLICATION SANDBOX

Your application. Its own Linux sandbox.

Keep dependencies separate

Install Linux packages for one project without mixing them with another sandbox. Choose Alpine or another compatible public Arm64 image with Pro.

Keep files between sessions

Stopping a sandbox keeps its writable files. Restart it to continue working. Shared Mac directories stay at the locations you select.

Control the runtime

Use terminal tabs for interactive work. Configure CPU cores, directory mounts and network options for Pro sandboxes.

MCP · PRO

A Linux workspace your agent can use.

Connect an MCP client to gLinux. A task gets its own sandbox; repeated commands with the same task ID share installed packages and files.

  1. Create a sandboxglinux_task_start

    Start a separate Linux sandbox for a task. Outbound network and writable Mac mounts are enabled only when requested.

  2. Build, test or runglinux_task_exec

    Execute Linux commands and receive stdout, stderr and an exit code.

  3. Continue interactivelyglinux_task_shell_open

    Open a PTY shell and exchange input and output for longer-running work.

Workflow examples: compile an Arm64 command-line program, run a project’s Linux tests, or inspect a sandbox’s files. MCP tasks are listed separately from terminal sandboxes in the app.
